# Hirschberg 1975, "A linear space algorithm for computing maximal common subsequences"

- URLs tried: https://dl.acm.org/doi/10.1145/360825.360861 (403), https://ics.uci.edu/~dhirschb/pubs/p341-hirschberg.pdf (curl: TLS "self-signed certificate in certificate chain", not bypassed; WebFetch: 503). Abstract text from the Crossref API (api.crossref.org/works/10.1145/360825.360861).
- Read: ABSTRACT ONLY (Crossref) plus the SECONDARY description in Myers 1986 (full text read). I did not read the paper's algorithm or theorem statements.
- Abstract, verbatim (Crossref): "The problem of finding a longest common subsequence of two strings has been solved in quadratic time and space. An algorithm is presented which will solve this problem in quadratic time and in linear space."
- Secondary (Myers 1986, Sec 1): "A later refinement by Hirschberg [7] delivers a longest common subsequence using only linear space." and Sec 4b: "As in the linear space algorithm of Hirschberg [7], a divide-and-conquer strategy is employed."
- The standard form of the idea (from general knowledge, not from this read): compute the LCS-length row forward for the first half of A and backward for the second half, pick the split column j* maximizing/minimizing the sum, recurse on both sides; O(NM) time, O(N+M) space.
- Does NOT transfer unchanged to our recurrence: it needs the forward value F(i,j) and the backward value B(i,j) of the SAME cell to be computed from row-vectors alone, with additive path cost F+B, and sub-problem costs fixed. In the top-down tree recurrence the DP edge weight dist(a_i,b_j) is itself an optimum over child lists below. That does NOT break Hirschberg: the edge weights are constants once memoised, and the meet-in-the-middle only needs additivity along the path. What breaks is cost, not correctness: reconstruction has to re-call dist for the cells of the recursion, so the memo table (O(pairs)) dominates the memory that the linear-space trick saves (question b in results/frontier).
